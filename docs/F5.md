# F5 — Yürütme katmanı

Sistemin **yazma yetkisi kazandığı** faz. Akış:

```
öner (prova) → İNSAN ONAYI → uygula → (gerekirse) geri al
```

Her adım denetim kaydına yazılır — **reddedilenler ve başarısızlar dahil**.

## Beyaz liste iki yerde birden zorlanır

| Katman | Ne yapar |
|---|---|
| Kod (`islemler.ts`) | Tanımsız işlem çağrılamaz; LLM SQL yazmaz, yalnızca tipli parametre önerir |
| **Veritabanı** (`sql/f5_yazma.sql`) | `ajan_yazar` kullanıcısının tabloya yazma yetkisi **yok**; yalnızca 2 saklı yordama `EXECUTE`. Üstelik `DENY INSERT, UPDATE, DELETE` var |

Kod katmanı aşılsa bile veritabanı reddeder. Saklı yordam içinden yazma
ownership chaining ile çalışır; doğrudan yazma `DENY` ile engellidir.

## Okuma ve yazma bağlantıları ayrı

- `ajan_okur` — `db_datareader`, hiçbir şey yazamaz. Her soruda çalışan LLM
  döngüsü **yalnızca bunu** kullanır.
- `ajan_yazar` — yalnızca onay sonrası, yalnızca yürütücü kullanır.

Amaç: istem enjeksiyonu ya da kod hatası okuma yolundan yazmaya sızamasın.

## Prova hiçbir şey değiştirmez

Prova okuma bağlantısını kullanır, bu yüzden yazma yapılandırılmamış olsa bile
çalışır. Çıktısı bir önce/sonra tablosudur:

```
HT10001 (ÖRNEK KAYIT) biletinin atanan kişisi "Ad Soyad" -> "Başka Kişi"
```

0 kayıt etkileyen öneri **onaya sunulmaz**.

## Kurulum

Yönetici PowerShell'de, `PAROLAYI_SEN_YAZ` değiştirilerek:

```
sqlcmd -S "localhost\SQLEXPRESS" -E -d gokkusagi_passwordvault -i sql5_yazma.sql
```

Sonra `.env`:

```
MSSQL_YAZAR_USER=ajan_yazar
MSSQL_YAZAR_PASSWORD=<parola>
```

Bu yapılana kadar sistem **yalnızca prova** modunda çalışır ve arayüzde
bunu açıkça söyler.
