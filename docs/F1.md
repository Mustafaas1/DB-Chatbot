# F1 — Araç Kaydı + MCP Yöneticisi + DB Okuma Aracı

Otonom iş zekâsı ajan sisteminin ilk fazı. Bu fazın çıktısı CLI'dan sürülebilen
bir araç katmanıdır; henüz LLM yok, soru cevaplamıyor.

## Çalıştırma

```bash
npm install
npm run cli -- liste
npm run cli -- sema veri_sorgula
npm run cli -- calistir veri_sorgula '{"sorgu":"SELECT TOP 5 BiletNo FROM dbo.TicketRecords"}'
npm test
```

`--prova` eklenirse araç gerçekten çalışmaz, ne yapacağını bildirir.

## Yapı

| Dosya | İş |
|---|---|
| `src/core/tools/tipler.ts` | Araç tipleri; her araç `yanEtki: okuma \| yazma` bildirmek zorunda |
| `src/core/tools/kayit.ts` | Araç kaydı: doğrulama, çalıştırma, Anthropic şeması üretimi |
| `src/core/db/guard.ts` | SQL güvenlik katmanı (Python `app/sqlguard.py`'den port) |
| `src/core/db/aracSorgu.ts` | `veri_sorgula` — salt-okunur T-SQL aracı |
| `src/core/mcp/yonetici.ts` | `mcp.json`'daki sunuculara bağlanır, araçlarını kayda ekler |
| `src/cli/index.ts` | CLI |

## Üç güvenlik katmanı

1. **`sqlDogrula`** — yalnızca SELECT/WITH, tek ifade, yasaklı kelime ve tablo taraması.
2. **Veritabanı izinleri** — `ajan_okur` kullanıcısı `db_datareader`; 8 hassas tabloya
   `DENY`. Koddaki katman aşılsa bile veritabanı reddeder.
3. **Satır ve süre sınırı** — `MAX_ROWS`, `QUERY_TIMEOUT`.

Python sürümünde bulunan üç gerçek bypass burada da kapalı ve her biri için test var:
metin sabiti içindeki `--` ile ifade gizleme, `[Users]` gibi tırnaklı yazımla yasaklı
tablo gizleme, ve `sys.sp_who` gibi nitelikli sistem prosedürü.

## Yazma araçları

`yanEtki: "yazma"` işaretli hiçbir araç şu an çalışmaz; `onay_gerekli` döner. Onay
katmanı F5'te geliyor. MCP'den gelen ve yan etkisini **bildirmeyen** araçlar da
"yazma" sayılır — bilinmeyeni okuma saymak dışarıdan gelen bir aracın sessizce
çalışmasına izin verirdi.
